# Сервер BHappy на бесплатном Render

Версия браузера: 0.3.0. Tor удалён. Для сетевого поиска и открытия сайтов нужен настоящий сервер BHappy. Он получает TCP соединения браузера через защищённый WebSocket (`wss://`) с ключом доступа. Случайный IP в интерфейсе не заменяет этот сервер.

Серверный код готов, но сервис в твоём аккаунте ещё не создан. Шаги ниже выполняются владельцем аккаунтов. Пароли, ключ Render API и ключ туннеля в чат присылать не нужно.

## 1. Подготовь репозиторий

Распакуй `BHappy-Tunnel-Server-0.3.0.zip`. В отдельном приватном репозитории GitHub размести содержимое распакованной папки: `package.json`, `package-lock.json`, `render.yaml`, `.dockerignore`, папки `server/` и `src/`. Эти файлы можно загрузить через GitHub → Add file → Upload files или отправить обычным Git push. В корне репозитория должен лежать `render.yaml`, без дополнительной внешней папки.

Отдельный серверный архив не содержит приложения, SDK, ключей и личных настроек. Полный архив исходников BHappy тоже подходит: в нём есть те же файлы и Dockerfile.

## 2. Создай бесплатный сервис

1. Войди на https://dashboard.render.com/ или создай аккаунт.
2. Выбери **New → Blueprint**, подключи GitHub и разреши доступ к выбранному приватному репозиторию.
3. Выбери репозиторий. Render прочитает `render.yaml`, в котором указан один Docker Web Service с планом **Free**. Проверь этот план до создания. База данных и платный диск не нужны.
4. Создай сервис и дождись статуса **Live**. Сборка запускает Node.js и сервер из `server/server.cjs`. Render самостоятельно предоставляет HTTPS/WSS сертификат.

Если используешь **New → Web Service** вместо Blueprint: укажи Docker, путь к Dockerfile `./server/Dockerfile`, план Free и health check `/healthz`. Добавь переменную окружения `BHAPPY_TOKEN`: случайный ключ минимум 32 символа. На странице Blueprint эта переменная создаётся автоматически.

## 3. Подключи браузер

1. На странице сервиса скопируй его публичный адрес, например `https://bhappy-example.onrender.com` — это пример, реальное имя даст Render.
2. Открой этот адрес с `/healthz`. После прогрева сервер ответит `BHappy tunnel`. Это проверка запуска сервера, а не проверка маршрута браузера.
3. В Render → Environment найди сгенерированную переменную **BHAPPY_TOKEN** и скопируй её значение. Не публикуй его в репозитории и не отправляй в переписку.
4. В BHappy открой панель подключения рядом с адресной строкой. В поле сервера введи свой адрес в формате `wss://bhappy-example.onrender.com/tunnel`; обязательно замени пример на реальный домен.
5. Вставь ключ и нажми **Подключить BHappy**. Затем введи поисковый запрос. Если он уже ожидал подключения, браузер повторит его автоматически.
6. Кнопка **Проверить выходной IP** делает отдельный запрос через туннель. Публичный IP принадлежит хостингу и не гарантированно меняется при переподключении.

Адрес и ключ в этой предварительной версии хранятся только до закрытия браузера. Подключи Windows и Android к одному серверу тем же способом. Уже работающий системный VPN может оставаться включённым: соединение с сервером BHappy пройдёт поверх него.

## Бесплатные лимиты

По [документации Render](https://render.com/docs/free), проверенной 15 ноября 2026 года, Free Web Service засыпает после 15 минут простоя и может запускаться снова около минуты. Если первое подключение не успело завершиться, дождись ответа `/healthz` и подключись повторно.

У аккаунта есть общий лимит бесплатных часов, исходящего трафика и времени сборки. Render может приостановить бесплатный сервис при интенсивном исходящем трафике; дополнительные объёмы при наличии способа оплаты могут тарифицироваться. Следи за Billing → Monthly Included Usage и выбирай именно Free. Это вариант для личных тестов в пределах лимитов, а не обещание бесплатного безлимитного VPN или постоянного сервера.

## Если не подключается

- `/healthz` не отвечает: проверь статус сервиса и Events/Logs в Render, дождись холодного запуска.
- Сервер отвечает, но ключ не принят: сравни `BHAPPY_TOKEN` и ключ в браузере. После смены переменной выполни Deploy, затем подключи браузер заново.
- Введён `https://` вместо `wss://` или потерян `/tunnel`: исправь адрес.
- Сервис приостановлен: проверь бесплатные лимиты. Браузер не обходит остановленный туннель прямым соединением.

Сервер запрещает доступ к локальным, частным и служебным IP, чтобы его нельзя было использовать для доступа во внутреннюю сеть хостинга. Tor и `.onion` адреса не поддерживаются. Туннель использует один выходной сервер; владелец сервера и хостинг остаются участниками доверия. Защита всей ОС при включении, независимый аудит анонимности и смена IP каждую секунду не реализованы.
